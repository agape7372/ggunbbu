- **config.ts `LANE_X=[180]` 근거 오류**: 주석 "원작엔 좌우 이동 없음(사용자 대조 확인)"은 코드와 배치.

**3차(같은 날) — 점프 중단 원인 규명, 밑면 접촉 판정 종결**: `+0x44`(vy)·`+0x40` 대입을 디컴파일
전수 + 바이너리 바이트 패턴 양쪽으로 스캔 → **범인 = `FUN_00405140`**(플레이어×층 충돌 **페어 노드**
처리기. 플레이어 자신의 상태 함수가 아니다). `switch(player[+0x50])`로 **포즈별 5-way** 분기:

| 포즈 | 밑면 접촉 시 |
|---|---|
| 1 지상공격 | 층 파괴 |
| **3·0xe 평범한 점프** | **정지**. `y_acc = L−0x2f`, `vy = building[+0x24]/128 + 1.0` |
| 4 공중공격 | **6프레임 선행 스윕**(`vy×6+y < L`)으로 **뚫으며 파괴** |
| 6 공중필살 | 정지. `y_acc = L−0x30`, `vy = building[+0x24]/128` (**+1.0 없음**) |
| 그 외 | 관통 |

**실측이 정수 단위로 일치**: 밑면선 `L=324` 유도 → `y=276` 미발동/`y=262` 발동 예측 적중 ·
`(0.359375−1.0)×128 = −82.0` 정수 = 건물 낙하 카운터 · vy 증분 정확히 1/128 · y 증분 정확히 +1px.

**→ DEVLOG:518 종결 = B 쪽(밑면 접촉). ROADMAP 08-30 정정이 옳았고 내 "관통 A" 판정이 틀렸다.**
단 **이분법이 아니라 포즈별 5-way**다 — 공중공격만 뚫고 부순다(이 비대칭이 원작 게임감의 핵심).
접촉 유지 중에는 매 프레임 재고정되어 **건물 침하 속도를 따라 내려간다**(vy=0 후 자유낙하가 아님).

**★교훈 2가지**: ① 부재 증명은 정적 분석으로 하지 마라 — 상호작용은 당사자 코드가 아니라 **중재자
코드**에 있다. ② 역산이 정수로 안 떨어지면 반올림하지 말고 **식을 의심하라**(`0.359×128=45.95`를
46으로 읽어 한 번 틀렸다. `+1.0` 항이 빠져 있었다).

**⚠ 계측 하네스 한계**: `memtrace.py`가 CSV를 매 실행 덮어쓴다(과거 런 미보존). 샘플레이트가
49,552/s ↔ 2,700/s로 요동하고 **61ms(≈4프레임) 무샘플 구멍**이 있다 — 이 하네스로 "N프레임 내
사건 없음" 류 **부정 명제를 세우지 말 것**.

**못 한 것**: `023/024.dat` 텍스트 미해독.
**함정 추가**: 백그라운드 프로세스에서 게임 창 포커스 획득은 **Alt 트릭 필수**
(`u32.keybd_event(0x12,…)` 감싸기) — `SetForegroundWindow` 단독도 `AttachThreadInput`도 실패한다.

**함정 기록**: `CopyFromScreen`/`gdigrab -i desktop`은 **z-order 최상단 픽셀**을 찍는다 — 창 좌표가
맞아도 다른 창이 덮으면 그걸 캡처한다(초기 캡처 전량이 사용자의 다른 게임을 찍은 오염 데이터였고,
"8bpp 게임인데 6944색"으로 발각). 창 격리 캡처는 **`PrintWindow(hwnd, hdc, PW_RENDERFULLCONTENT=2)`**.
그리고 exe 실행은 `save/replay*.rep` 링버퍼를 밀어낸다(DeleteFileA+MoveFileA) — 사본에서만 실행할 것.

## 2026-08-21 — 원본 대조 (조작감 교정)

원작 배포본을 개발자 공식 홈페이지에서 받아 **에셋·설명서를 해부**했다(EXE 실행은 하지 않음 —
신뢰 불가 바이너리 실행 금지 정책). 게임 메커니즘·수치는 사실이라 참고하되, 원본 그래픽·음악은 미사용.

**정적 분석**: 네이티브 C++(MSVC) + DirectDraw 8bit 팔레트 + DirectSound + `timeGetTime`.
화면 **640×480 가로**(title.bmp / bg.bmp 640×1440 = 3화면). 자산 88개 전부 비암호화.

### 발견한 내 구현의 근본 오류 (조작감 차이의 주범)

1. **게이지가 2개다** — 개발자 설명서 원문: 방어 게이지(핑크, 가드 전용) / 기술 게이지(황색,
   콤보로 충전·필살기 전용). 에셋도 일치(`bougyobar.bmp` 100×16, `wazabar.bmp` 50×4).
   나는 하나로 합쳐 **가드할 때마다 필살기 자원이 깎이는** 전혀 다른 자원 관리 게임이 되어 있었다.
   → `guardGauge` / `wazaGauge` 분리. 방어는 놓으면 회복(REGEN 14/s, 대기 24f)해 반복 사용 전제.
   설명서의 "방어를 콤보보다 먼저 익혀라"가 성립하려면 가드가 상시 쓸 수 있어야 한다.
2. **점프 = 무적** — 설명서: "공중에서는 짓눌리지 않음". 점프가 정식 회피기인데 내 구현은
   공중이든 지상이든 접지 시 깔렸다. → 공중이면 피해 없음, 놓인 스택 위로 **착지할 때** 깔린다.
3. **연타가 느렸다** — 원작 `slash.wav` = **88ms**. 공격 프레임 9f(150ms, 6.7타/s) → **6f(100ms, 10타/s)**.
4. **밀어올림 과다** — 설명서가 가드를 주 방어 수단으로 명시 → 연타만으로 버티면 안 된다.
   `HIT_LIFT_V` 170 → 80.

### 1. `023/024.dat` 해독 완료
로더 `FUN_00408f50` @ `0x408f50`. **조건부 XOR 0x3A + Shift-JIS**:
바이트 `< 0x20` 은 그대로(그래서 CRLF가 평문으로 남아 있었다), `>= 0x20` 이면 XOR 0x3A,
단 결과가 `0x20` 미만이 되면 XOR 취소. `0xFF` 는 리스트 종료 센티널.
023 = 오프닝 내레이션, 024 = 연표 + 엔딩 + 스태프 크레딧. 한국어 재배포판인데 **이 둘만 일본어 원문**.

★ **단순 브루트포스로는 못 찾는 문제였다.** XOR 0x00~0xFF 전수 중 0xD9가 cp932를 코덱 에러 없이
통과한다 — 내용은 쓰레기인 거짓양성. 디컴파일로 로더를 짚어야만 풀린다.

### 2. 세 충돌 처리기 담당 확정
