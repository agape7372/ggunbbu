## 2026-08-21 — 원본 대조 (조작감 교정)

원작 배포본을 개발자 공식 홈페이지에서 받아 **에셋·설명서를 해부**했다(EXE 실행은 하지 않음 —
신뢰 불가 바이너리 실행 금지 정책). 게임 메커니즘·수치는 사실이라 참고하되, 원본 그래픽·음악은 미사용.

**정적 분석**: 네이티브 C++(MSVC) + DirectDraw 8bit 팔레트 + DirectSound + `timeGetTime`.
화면 **640×480 가로**(title.bmp / bg.bmp 640×1440 = 3화면). 자산 88개 전부 비암호화.

### 발견한 내 구현의 근본 오류 (조작감 차이의 주범)

1. **게이지가 2개다** — 개발자 설명서 원문: 방어 게이지(핑크, 가드 전용) / 기술 게이지(황색,
   콤보로 충전·필살기 전용). 에셋도 일치(`bougyobar.bmp` 100×16, `wazabar.bmp` 50×4).
   나는 하나로 합쳐 **가드할 때마다 필살기 자원이 깎이는** 전혀 다른 자원 관리 게임이 되어 있었다.
   → `guardGauge` / `wazaGauge` 분리. 방어는 놓으면 회복(REGEN 14/s, 대기 24f)해 반복 사용 전제.
   설명서의 "방어를 콤보보다 먼저 익혀라"가 성립하려면 가드가 상시 쓸 수 있어야 한다.
2. **점프 = 무적** — 설명서: "공중에서는 짓눌리지 않음". 점프가 정식 회피기인데 내 구현은
   공중이든 지상이든 접지 시 깔렸다. → 공중이면 피해 없음, 놓인 스택 위로 **착지할 때** 깔린다.
3. **연타가 느렸다** — 원작 `slash.wav` = **88ms**. 공격 프레임 9f(150ms, 6.7타/s) → **6f(100ms, 10타/s)**.
4. **밀어올림 과다** — 설명서가 가드를 주 방어 수단으로 명시 → 연타만으로 버티면 안 된다.
   `HIT_LIFT_V` 170 → 80.

### 계측 자료 (scratchpad/kirubiru/)
`MANUAL_ko.md`(설명서 번역) · `SOUNDS.md`(효과음 16종 길이) · `DATA_FILES.md` · `EXE_STRINGS.txt`.
효과음 길이가 곧 리듬이다: slash 88ms / tyakuti(착지) 96ms / jump 175ms / bougyo(방어) 200ms /
kaminari(번개) 268ms / waza(필살기) 947ms.

### 부수 영향
- 연타 2배 → 대미지·점수 상승. 1막 10분 실측 5.1M → **7.88M**(목표 밴드 유지, 재튜닝 불필요).
- 보스전 봇 완주 불가(강화 패턴 도달이 앞당겨짐). 대성당과 동일 판단으로 **수용 기준을 구조
  검증으로 전환**(HP 회계·티어 전이·격파 경로). 봇 정책 개선은 수확 체감이라 중단.
- 테스트 42 → **48개** (점프 무적 2, 게이지 분리 3, 보스 구조 2).

### 남은 대조 항목
- 화면비: 원작 **640×480 가로** vs 현재 **360×640 세로**. 레인 폭·건물 비율이 근본적으로 다르다.
  모바일 세로를 유지할지, 가로 모드를 도입할지는 사용자 결정 필요.
- 콤보 팝업: 원작은 타격마다 숫자가 화면에 흩뿌려져 여러 개가 동시에 뜬다(영상 확인). 현재는 3개 상한.
- 스프라이트 기하 계측(레인 폭·층 높이·캐릭터 크기) 진행 중.
